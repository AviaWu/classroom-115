# 畫板資料拆分設計

## 目標

將畫板 JPEG Data URL 從每 5 秒讀取的班級進度中移出，保存到 `/artworks/classroom-115/{drawingId}`。一般進度同步只取得畫作索引；只有畫板或老師後台畫冊需要顯示作品時才讀取圖片。

維持既有規則：頁面載入先讀雲端最新進度、本機資料不自動上傳、操作即時寫入、進度不分版本、離線時顯示「離線中」。

## 資料結構

```text
/games/classroom-115
  progress
    drawings
      0
        id: "drawing_uuid"
        savedAt: "2026-09-16T00:00:00.000Z"
      1: ...
      2: ...
    drawingAlbum
      0
        id: "drawing_uuid"
        savedAt: "2026-09-15T00:00:00.000Z"
      ...
  operations
  lastOperationId
  restoredAt

/artworks/classroom-115
  drawing_uuid
    id: "drawing_uuid"
    savedAt: "2026-09-16T00:00:00.000Z"
    data: "data:image/jpeg;base64,..."
```

`progress.drawings` 只保留最近三筆索引；超過三筆的索引移入 `progress.drawingAlbum`。兩個陣列都不保存 `data`。圖片節點必須位於 `/games/classroom-115` 之外，避免每次班級根節點交易讀取圖片。

畫作 ID 必須沿用 `drawing_` 前綴並以英數字、底線或連字號組成，長度為 8 至 128 字元；這同時相容既有時間戳 ID 與新版 UUID ID。圖片資料必須是 JPEG 或 PNG Data URL，完整字串最多 1,500,000 字元，避免匿名客戶端寫入無限制資料。

## 一般進度同步

現有每 5 秒讀取 `/games/classroom-115/progress` 的流程維持不變。由於 `drawings` 與 `drawingAlbum` 只剩索引，輪詢不下載圖片內容。

一般畫面更新只根據畫作索引判斷最新作品，不能因為圖片尚未載入而刪除索引或回寫空資料。進度正規化器接受 `{id, savedAt}`，不再要求 `data` 欄位。

## 畫板行為

開啟畫板時立即取得 `progress.drawings` 的最新三筆索引，並分別讀取 `/artworks/classroom-115/{drawingId}`。畫板保持開啟時，每 5 秒使用一般進度同步後的最新索引更新縮圖：

1. 比較目前顯示的三個畫作 ID 與最新索引。
2. 已載入且 ID 未變的圖片使用記憶體快取，不重複下載。
3. 新出現或尚未載入的 ID 才讀取對應圖片節點。
4. 已不在最近三筆的縮圖從畫板移除，但圖片仍保留在作品節點，供老師畫冊查看。
5. 單張圖片讀取失敗時顯示該縮圖無法載入，不影響其他兩張或一般進度同步。

因此畫板畫面仍每 5 秒看到其他裝置新增的最新作品，但沒有變更時不會反覆下載相同圖片。

## 儲存畫作

畫板儲存使用同一個固定畫作 ID，流程如下：

1. 將 `{id, savedAt, data}` 冪等寫入 `/artworks/classroom-115/{drawingId}`。
2. 成功後送出 `saveDrawing` 班級操作；命令只攜帶 `{id, savedAt}`。
3. 班級交易把索引加入 `progress.drawings`，只保留最近三筆，其餘索引移到 `drawingAlbum`。
4. 若圖片寫入成功但索引交易尚未確認，重試沿用相同 ID，不會建立重複作品。
5. 若索引最終未建立，圖片成為無索引的孤立資料；程式不把它顯示為作品，可由後續維護工具清理。這比先建立索引、卻讓使用者看到不存在的圖片安全。

待確認操作仍保存原始畫作資料，確保網路中斷後可用同一 ID 完成圖片寫入。畫作成功建立索引後，待確認資料立即清除。

## 老師後台畫冊

老師進入「畫冊」頁時，合併 `progress.drawings` 與 `progress.drawingAlbum` 的索引，讀取所有對應圖片一次並顯示完整畫冊。

畫冊頁保持開啟期間不執行 5 秒圖片輪詢，也不因一般進度刷新而自動下載新圖片。老師關閉後重新進入畫冊時再重新載入；頁面提供「重新整理畫冊」按鈕，只有老師主動按下時才重新讀取索引和圖片。

已載入的圖片在目前頁面生命週期內使用記憶體快取。重新整理畫冊時，ID 未變的圖片沿用快取，只下載新 ID；永久刪除的 ID 從畫面與快取移除。

## 刪除畫作

老師永久刪除畫作時：

1. 先以班級交易從 `drawings` 或 `drawingAlbum` 移除索引。
2. 索引交易成功後刪除 `/artworks/classroom-115/{drawingId}`。
3. 圖片刪除失敗時不把索引加回；記錄錯誤並允許老師重試清理。沒有索引的圖片不會被一般使用者下載。

## 備份、還原與舊資料遷移

下載備份時先讀最新 `progress`，再依所有畫作索引讀取圖片，輸出與既有格式相容的單一 JSON：備份內的 `drawings` 與 `drawingAlbum` 每筆都重新包含 `data`。尚未遷移的舊畫作直接使用進度內既有的 `data`。任何圖片讀取失敗時停止產生備份並列出缺少的畫作，避免建立不完整備份。

還原既有備份時，先將每筆畫作的 `data` 寫入獨立作品節點，再以不含 `data` 的索引還原 `progress`。所有圖片寫入成功後才提交進度還原操作；重試沿用備份中的畫作 ID。

部署新版後，第一次讀到仍在 `progress` 內含 `data` 的舊畫作時只在記憶體辨識為待遷移，不因開頁自動寫入。老師後台「備份」頁提供明確的「遷移畫作資料」操作：老師確認後，依序寫入獨立作品節點，最後用單一班級交易把 `progress` 畫作轉為索引。全部作品寫入成功前不移除舊 `data`，所以中途失敗可安全重試。

## Firebase 規則

`database.rules.json` 新增 `/artworks/classroom-115/{drawingId}` 規則：

- 沿用目前的匿名登入要求。
- 節點鍵與 `id` 必須一致；ID 以 `drawing_` 開頭、只含英數字／底線／連字號，長度 8 至 128 字元。
- `savedAt` 必須是 20 至 40 字元的 ISO 8601 字串。
- `data` 必須符合 JPEG 或 PNG Data URL 前綴，完整字串最多 1,500,000 字元。
- 一般進度規則要求 `drawings` 與 `drawingAlbum` 項目只能保存 `id`、`savedAt`，不得再保存 `data`。

這些規則延續現有合作式匿名客戶端的安全邊界，不新增教師身分授權系統。

## 錯誤與離線行為

- 一般進度成功、圖片讀取失敗：一般功能保持可用，畫作位置顯示載入失敗。
- 離線開啟畫板或畫冊：顯示「離線中」，不把本機圖片回寫雲端。
- 儲存圖片失敗：不送出畫作索引操作，保留同一筆待確認資料供重試。
- 索引操作回應遺失：依既有操作收據查證，不重複建立畫作。
- 舊資料尚未遷移：仍可顯示舊 `data`；背景輪詢會繼續下載舊圖片，直到老師完成一次明確遷移。

## 測試與驗收

- 單元測試確認 `saveDrawing` 只保存索引，最近三筆與畫冊排序維持一致。
- 儲存介面測試確認畫作路徑讀、寫、刪除及相同 ID 重試。
- Firebase 模擬器測試確認畫作規則、大小限制、無效 Data URL，以及一般進度拒絕嵌入圖片。
- DOM 整合測試確認一般 5 秒刷新不讀圖片、畫板開啟時只讀最新三張、相同 ID 不重複讀取、畫板新增作品時只讀新 ID。
- DOM 整合測試確認老師畫冊開啟時載入一次，保持開啟超過 5 秒不再讀圖，按「重新整理畫冊」才取得新作品。
- 備份與還原測試確認輸出仍包含全部圖片，缺圖不產生不完整備份，舊格式可還原。
- 遷移測試確認開頁不寫入、部分失敗不刪除舊資料、重試成功後才從進度移除 `data`。

以 2026-09-14 的現有備份估算，一般進度單次讀取可由約 308 KB 降至約 24 KB；畫作 metadata 增加量很小。實際傳輸量仍以部署後 Firebase Usage 與瀏覽器網路紀錄驗證。
